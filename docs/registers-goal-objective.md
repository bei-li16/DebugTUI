## 3. 必须落实的行为

### 公共模型、配置与来源

- 支持每核独立 CPU、目录和访问参数；覆盖同型多核、非连续核编号与 M7＋M4 异构多核。芯片拓扑/连接参数、核型号寄存器定义、后端访问能力分别管理。
- 核对规格的配置优先级并映射到现有配置体系；Setup/Status 展示每核最终值、声明文件、覆盖来源、实际路由与观测冲突。芯片配置不能悄悄改写核定义的编码、字段和复位值。
- 公共定义采用 `extends`，型号只写增量；同名覆盖必须 `override=true`，拒绝循环、超深、歧义及不完整覆盖。保留实际声明文件与继承链。
- 保留 reset、结构化 source、confidence、present_if、访问条件及读副作用。缺少依据为 Unknown/fields_missing；冲突并列记录。条件使用有限结构化比较，不引入表达式语言。
- 复用 GDB、MMIO、CorePrivate、CP15/MRRC、Banked、VFP、Backend、Alias 等已有 reader。显示分组及 RO/RW 属性不授予访问或写入能力。Alias 不得绕过父项的存在性、权限、owner 或副作用限制。
- owner 明确为 core/cluster/chip/unknown；缓存、Watch、样本与请求包含 owner、实际访问核、路由及上下文。未知 owner 不猜测、不发数据请求；同地址不等于同对象。
- 已有 3～5 项代表性定义与格式验收继续复用；格式未变时不重做样例流程。需要新格式时先验证代表样例，再按实际需要迁移，不继续扩大无用目录。

### Cortex-M3/M4/M7

- 内置 `armv7m-common` 及 M3/M4/M7 增量。常用 SCB/故障字段、NVIC、SysTick、MPU、Debug、DWT/FPB 身份容量、M4 FPU 配置身份及 M7 cache/TCM 定义有来源且能接通实际 reader。
- 复用固定版本 CMSIS 核头文件与离线转换脚本，记录来源摘要、行号及许可证；手册补充 CMSIS 未定义的字段、复位值与副作用。生成结果通过继承、编码、位域、来源和一致性检查。
- 通过 CPUID、ICTR、MPU_TYPE 等实际观测决定型号和动态实例；不按芯片名称硬编码容量。ICTR 是中断线数上限，真实中断使用 SVD。NVIC 优先级位数来自 SVD/显式声明，缺失为 Unknown；本版不写 IPR 探测。
- CorePrivate 的相同 PPB 地址必须走各核自己的 AP/target。用 M7＋M4 验证目录、身份、数值、错误、路由、缓存和旧样本隔离，不能只验证不同名字的模拟响应。
- MPU region 与 M7 CSSELR/CCSIDR 复用受保护事务：保存、选择、读取、恢复、回读验证。只读允许必要的临时 selector/scratch 写入，但不持久修改 MPU/cache/TCM 配置。
- DWT/FPB/FPU 等可选模块区分未实现、未知及未使能；NeedEnable 提示具体依赖，不能自动使能。缺失的受使能限制数据不等于模块不存在。
- DHCSR、SysTick CTRL 等读副作用项仅明确手动单次读，自动队列、轮询、Probe 与复位扫描零 I/O。状态检测复用既有 GDB/OpenOCD 状态事件，不轮询 DHCSR。
- 按寄存器、实际路由和后端能力判断 NeedHalt。安全运行态 AP/MMIO 必须有真实成功路径；GDB regfile、借核执行及要求停止的 selector 保持停止限制。元数据 `need_halt=false` 不能单独授权运行态读取。
- 运行态样本记录实际请求区间与上下文；采样期间状态、owner 或路由改变，或响应迟到时不能作为当前值。维护命令、WO 寄存器可以显示定义，不能作为普通读执行。

### Cortex-R52

- 完整核对并接通常用身份/控制与 MPU：MIDR、MPIDR、SCTLR、HSCTLR、CPACR、HCR、MPUIR、HMPUIR、PRSELR、HPRSELR、MAIR0/1、HMAIR0/1，以及实际容量内 EL1/EL2 MPU region。包含正确编码、宽度、主要字段、访问条件及手册来源。
- 普通 CP15、MPU 与 selector 共用一致的当前 Debug 权限判断。停止前保存的 CPSR/DSPSR、halt 状态、配置声明不能单独证明当前 Debug EL。只处理本版实际后端与寄存器需要的执行状态、授权/trap 条件，不建立超出本版的通用权限框架。
- 当前 Debug 状态规则以 `DDI 0568A.c` 的 R-profile 定义为准；重点核对 EDSCR.HDD 位 15、位 16 为 RES1，以及状态保存和恢复所用掩码。分别验证合法 RES1 状态、HDD 限制、故障状态、未完成指令和传输标志变化。正确解码当前 EL 只是访问证明的一部分，不能据此给任意 CP15 指令统一放行。
- 证明绑定实际核心、会话、后端和当前事务；缺失、过期或不满足时在数据指令前明确拒绝。本版只放行已逐项核对的当前 Debug EL2、有界 R52 寄存器；不将 EL2 当作任意 CP15 的通用授权。软件验收必须通过真实 host worker 与实际生产 C 事务模型覆盖普通 CP15、MPU 和 selector 的成功读取；全部返回 Unknown 不算完成。完整后端构建与命令入口另行验收，不要求通过实板执行满足本 Goal。
- 复用现有 OpenOCD 生产流程与服务锁，验证 scratch/selector 保存恢复及回读。若修改 OpenOCD，软件测试覆盖实际 C 事务代码，硬件边界可用独立夹具；预设成功字符串不能代替生产路径测试，也不能被宣称为实板验证。
- selector 在后端单个保护事务内完成：核实当前 Debug 证据和本 bank 新鲜容量，保存并验证原 selector，选择及回读，读取 BAR/LAR，恢复及回读，再复核状态。零容量、非法原 selector 或越界索引在 selector 写入前拒绝；使用真正 ISB，不用修改控制寄存器换取屏障能力。不能向旧 Plan 传固定 Hyp 模式伪造权限。
- 异常、取消、超时、断线及恢复不确定时不发布部分成功；实际注入故障后停止后续指令，不盲目恢复或重试，保持 FAULT/隔离并提示重连。正常完成事务后的取消只丢弃结果。只有执行前确定命令不支持且替代路径已验证时允许选择另一条路径。
- 保留 R52+ 入口，但差异和身份未验证时明确 Unknown/Unsupported；无法证明的低 EL/Guest/trap 情形明确受限。本版不通过改 CPU 模式、权限或控制寄存器取得访问。
